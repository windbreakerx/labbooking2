## 3. Этап 1. Схема и целостность

### Модели

- `LabSession.capacity` удалён из базы. Вместо него свойство:
  - групповая бронь — размер группы-оккупанта;
  - обычная — `lab_work.capacity`.
- `LabSession.used_stands` удалён.
- `LabWork.primary_stand` заменён на `LabWork.stands` (M2M): набор одинаковых стендов ЛР.
- `LabWork.is_archived` и `Discipline.is_archived` добавлены.
- `Booking.lab_session`, `Booking.lab_work`, `Booking.discipline` переведены с `CASCADE` на `PROTECT`.
- `LabSession.lab_work` переведён на `PROTECT`.
- Добавлен частичный уникальный индекс `bookings_one_active_per_slot`.
- Добавлены `CHECK capacity >= 1` для `Room` и `LabStand`.

### Миграции

- `apps/academics/migrations/0004_remove_labwork_primary_stand_discipline_is_archived_and_more.py`
- `apps/scheduling/migrations/0007_remove_labsession_capacity_and_more.py`
- `apps/scheduling/migrations/0008_alter_labsession_lab_work.py`
- `apps/bookings/migrations/0008_alter_booking_discipline_alter_booking_lab_session_and_more.py`

### Поведение

- Удаление ЛР со слотами в портале переводит её в архив.
- Архивные ЛР и дисциплины скрыты из студенческого каталога, форм и выбора слота.
- История записей и слотов остаётся доступной.
- `archive_old_data` по умолчанию только отчитывается, удаляет по `--apply` и не трогает слоты с записями.

### Тесты

- второй `BOOKED` на тот же слот падает;
- после отмены повторная запись проходит;
- удаление слота, ЛР и дисциплины с записями запрещено;
- архивная ЛР не видна студенту;
- нулевая вместимость комнаты и стенда не сохраняется;
- удаление ЛР со слотами в портале архивирует её.

## 4. Этап 2. Места, стенды, аудитории

### Сервисы

- `seat_capacity.py` упрощён:
  - убран общий лимит ЛР (`lab_other`, `lab_work_capacity`);
  - аудитория ограничивает всегда, `room_remaining` больше не `None`;
  - стенд занят, если чужая ЛР использует тот же стенд или в комнате кончились стенды этой ЛР.
- `session_catalog.py` считает только нужные счётчики и пакетно проверяет стенды.
- `session_admin.py`:
  - убраны `_default_capacity`, `_booked_count_guard`, поле вместимости;
  - добавлены проверка конфликта преподавателя и проверки стендов.
- `session_bulk.py` больше не переносит вместимость и стенды.
- `booking.py`:
  - ручная запись блокируется только занятым стендом;
  - предупреждение только о переполнении аудитории;
  - превышение пишется в `AuditLog` действием `booking.overflow`;
  - удалён неиспользуемый `skip_student_rules`.
- `waitlist.py` проверяет `session.available_seats`.
- `catalog_admin.py`:
  - `update_room` пишет аудит `room.update` со старым и новым значением и возвращает переполненные слоты;
  - добавлено предупреждение, если вместимость ЛР больше вместимости стенда.
- `views/catalog.py` показывает предупреждение после уменьшения аудитории.

### Отчёты

- Добавлен отчёт «Переполненные слоты»: `overflow_rows`, `export_overflow_xlsx`, страница `/staff/reports/overflow/`, карточка на лендинге отчётов.

### Тесты

- одиночный слот и лимит комнаты;
- две комнаты с одинаковыми стендами: по 3 человека, всего 6;
- параллельные пары одной ЛР в одной комнате ограничены комнатой;
- разные ЛР с общим стендом не пересекаются;
- один стенд — вторая параллельная пара не создаётся;
- два стенда в одной комнате — две параллельные пары разрешены;
- два стенда в двух комнатах — по одной паре;
- слот в комнате без стенда отклоняется;
- ЛР без стендов может идти параллельно;
- ручное переполнение даёт предупреждение и аудит;
- уменьшение комнаты показывает затронутые слоты;
- `join_waitlist` учитывает лимит комнаты.

## 5. Этап 3. Расписание

- `create_series`, `_copy_sessions` и `cancel_series` выполняются в транзакциях.
- Ошибки серии и копирования получают дату: `12.12.2026: У преподавателя уже есть пара`.
- `cancel_series` считает записи студентов, а не слоты.
- Чужая аудитория в `cancel_series` возвращает ошибку, а не молчаливый ноль.
- `copy_week` требует понедельники.
- Проверки преподавателя и стендов работают и в массовых операциях.
- Разные ЛР по-прежнему могут делить комнату, если позволяет вместимость.

Тесты:

- серия откатывается при конфликте на третьем слоте;
- копирование откатывается при конфликте стенда;
- превью отмены показывает число записей;
- невыровненные даты недели отклоняются;
- две разные ЛР в одной комнате на одно время создаются.

## 8. Этап 6. Очередь

- `_promote_waitlist_with_retry` открывает транзакцию и берёт `select_for_update` на слот.
- Затем читает первую запись очереди с `select_for_update`.
- После блокировки очередь перечитывается: если записи уже нет, выхода без уведомления.
- Порядок блокировок «слот → запись» совпадает с `BookingService`.

Тесты:

- две последовательные отмены приглашают двух участников;
- удалённая запись не даёт ложного «вы выбыли»;
- ошибка записи по-прежнему выкидывает участника с уведомлением.

## 9. Этап 7. Доступ

### Скоупы

- `staff_rooms_qs`:
  - `LAB_ADMIN` — комнаты с `default_lab_staff = user`;
  - `LAB_HEAD` — все комнаты своей лаборатории;
  - `SYS_ADMIN` — все;
  - `TEACHER` — ничего.
- `staff_bookings_qs`:
  - преподаватель — только брони слотов, где `teacher = user`;
  - сотрудник и завлаб — вся лаборатория.
- `staff_sessions_qs`: преподаватель — свои слоты; сотрудник и завлаб — лаборатория.

### Запись и статусы

- `BookingService` при ручной записи проверяет комнату.
- `BookingMutationsMixin` проверяет комнату при смене статуса, отмене и отмене слота.
- Преподавателю менять статусы и писать вручную запрещено.
- `staff_writable_lab_works_qs` и `staff_manual_slots` ограничивают ручную запись доступными комнатами.
- В таблице броней кнопки скрыты для чужих комнат.
- Сотруднику без назначенных комнат показывается подсказка «обратитесь к завлабу».

### Тесты

- преподаватель не видит чужие слоты и брони, XLSX содержит только его строки;
- сотрудник видит всю лабораторию, но не может писать в чужую комнату;
- завлаб может всё в своей лаборатории и ничего в чужой;
- сотрудник без комнат видит данные, но не кнопки изменения.

- XLSX-отчёты собираются в памяти. Потоковая выгрузка отложена: для пилотных объёмов этого достаточно.
- Уведомления пишутся только в лог, транспорт не подключён. Это явно указано в документации.
- Тесты очереди моделируют повторный промоушен, а не два реальных потока; корректность обеспечивает блокировка слота.
- `staff_rooms_qs` завлаба включает комнаты с `laboratory = его лаборатория`; комнаты без лаборатории в его УЦ остаются только для чтения.
