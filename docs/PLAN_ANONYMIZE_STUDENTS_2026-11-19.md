# План: одноразовый скрипт обезличивания списка студентов

**Проект:** labbooking2-main
**Дата:** 19.11.2026
**Статус:** план, к реализации не приступали
**Область:** подготовка CSV для `import_dekanat_csv --type students`

## 1. Цель

Подготовить обезличенный CSV со студентами из настоящего списка, чтобы загрузить его в тестовую/демо-базу labbooking2 и не хранить в ней фамилии, имена, отчества, телефоны, email и реальные идентификаторы студентов.

Скрипт живет **вне репозитория** (`C:\anon-labbooking\`), в git не попадает, в `requirements.txt` проекта не добавляется. Faker используется как обычная внешняя зависимость в отдельном venv.

## 2. Что входит и что не входит

**Входит:**

- чтение реального CSV студентов;
- замена ФИО на синтетические (Faker, locale `ru_RU`) с сохранением пола;
- замена `dekanat_id`, `student_id`, `email`, `phone`;
- удаление/обнуление паролей;
- детерминированные псевдонимы, чтобы повторный импорт обновлял, а не дублировал студентов;
- валидация результата и импорт в пустую тестовую БД.

**Не входит:**

- изменение кода labbooking2;
- добавление `faker` в зависимости проекта;
- обезличивание преподавателей, сотрудников, дисциплин и расписания (отдельная задача, если понадобится);
- юридическая оценка 152-ФЗ: это подготовка тестовых данных, а не средство анонимизации реальной системы.

## 3. Контракт с `import_dekanat_csv`

Команда читает `csv.DictReader` с `utf-8-sig` и разделителем `,` (по умолчанию). Для `--type students` используются колонки:

| Колонка | Обязательность | Поведение команды |
|---|---|---|
| `group` | желательно | привязка к `StudentGroup` по имени, если группа уже импортирована |
| `dekanat_id` | ключ дедупликации | первый приоритет поиска существующего профиля |
| `student_id` | ключ дедупликации | второй приоритет |
| `email` | ключ дедупликации | третий приоритет; при пустом значении генерируется `student-<hint>@demo.local` |
| `first_name` | да | поле пользователя |
| `patronymic` | нет | склеивается с `first_name` через пробел: `Имя Отчество` |
| `last_name` | да | поле пользователя |
| `faculty` | нет | текст в профиль |
| `gender` | нет | только `M` или `F` |
| `phone` | нет | текст в профиль |
| `password` | нет | пароль только при создании/`--reset-passwords` |

Важные следствия:

1. **Порядок частей имени:** в `User.first_name` должно быть `Имя Отчество` (свойство `greeting_name` берет первые два слова, `header_name` строит инициалы из них).
2. **Дедупликация:** если псевдонимы `dekanat_id`/`student_id` меняются от прогона к прогону, повторный импорт создаст новых пользователей.
3. **Email:** лучше заполнять явно (`s-<псевдоним>@demo.local`), чтобы не зависеть от того, из какого поля команда соберет hint.
4. **Группы:** `students` ссылается на уже существующую `StudentGroup`. Если имена групп тоже меняются, одно и то же отображение обязано применяться и к `groups.csv`, и к `students.csv`.

## 4. Правила обезличивания

| Поле | Правило |
|---|---|
| `last_name` | `fake.last_name_male()` / `fake.last_name_female()` |
| `first_name` | `fake.first_name_male()` / `fake.first_name_female()` |
| `patronymic` | `fake.middle_name_male()` / `fake.middle_name_female()` (проверить наличие метода при старте) |
| `gender` | нормализовать `М/Ж/m/f/male/female` → `M/F`; если пусто — выбрать детерминированно и записать |
| `dekanat_id` | `STU-D-<hmac_sha256(secret, "dekanat:" + value)[:10]>` |
| `student_id` | `STU-S-<hmac_sha256(secret, "student:" + value)[:10]>` |
| `email` | `s-<нижний регистр псевдонима student_id или dekanat_id>@demo.local` |
| `phone` | пустая строка (не генерировать: телефоны не нужны для сценариев) |
| `password` | колонку удалить; пароль задавать при импорте через `--default-password` |
| `group`, `faculty` | по умолчанию оставить; при требовании политики — заменить по общей карте групп |
| остальные колонки | **удалить**: белый список полей, все неизвестные колонки отбрасываются (там могут быть СНИЛС, дата рождения, адрес) |

Дополнительно:

- пространства имен в HMAC (`dekanat:`, `student:`) не дают одинаковым значениям в разных полях давать одинаковый псевдоним;
- если оба ID пусты, fallback — HMAC от нормализованного реального email; если пуст и email — строка помечается ошибкой и не попадает в выход (нельзя строить ключ от ФИО: коллизии и нестабильность);
- имена могут повторяться, это нормально; email обязан быть уникальным — это обеспечивается уникальностью псевдонима;
- секрет (`ANON_SECRET`, 32+ случайных байта) хранится вне репозитория, передается через файл/переменную окружения, не через аргумент командной строки.

## 5. Структура каталога снаружи репозитория

```
C:\anon-labbooking\          # вне git, вне OneDrive/общих папок
├── .venv\                   # отдельное окружение
├── requirements.txt         # Faker==<точная версия>
├── anon_students.py         # скрипт
├── verify_output.py         # проверки (можно режимом --verify внутри основного)
├── config.toml              # домен email, пути, режимы, без секрета
├── input\
│   └── students.real.csv    # настоящий список, не коммитить
├── output\
│   ├── students.anon.csv    # результат для импорта
│   └── report.json          # счетчики и предупреждения, без ПДн
├── mapping\
│   └── students.map.csv     # реальный ID → псевдоним (ключ деанонимизации)
└── logs\
```

Правила:

- `input`, `mapping`, `output` не попадают ни в один git-репозиторий;
- `mapping` после успешного импорта удаляется, если возврат к реальным ID не нужен;
- в `report.json` только счетчики и номера строк, без значений полей;
- реальные ФИО/телефоны/email не попадают в логи, консоль и сообщения об ошибках (выводить номер строки и имя поля).

## 6. CLI и алгоритм скрипта

Предлагаемый интерфейс:

```
python anon_students.py \
  --input input/students.real.csv \
  --output output/students.anon.csv \
  --mapping-out mapping/students.map.csv \
  --report output/report.json \
  --secret-file ..\secret\anon.key \
  --email-domain demo.local \
  --seed 42 \
  --encoding utf-8-sig \
  --delimiter "," \
  [--keep-groups] \
  [--group-map input/group-map.csv] \
  [--verify] \
  [--dry-run]
```

Алгоритм:

1. Прочитать `config`/аргументы, проверить существование входа и права на выход.
2. Загрузить секрет, проверить длину >= 32 байт.
3. Проверить Faker: locale `ru_RU`, наличие `first_name_male`, `last_name_male`, `middle_name_male` и female-аналогов; при отсутствии — остановиться с понятным сообщением.
4. Прочитать CSV, проверить заголовок: обязательны `first_name`, `last_name`; предупредить об отсутствии `gender`, `dekanat_id`, `student_id`, `email`.
5. Для каждой строки:
   - нормализовать и проверить ID; вычислить псевдонимы;
   - определить пол; сгенерировать ФИО с `Faker.seed(int(hmac_hex, 16))` (reseeding на строку, а не глобально один раз);
   - собрать email от псевдонима, очистить телефон и пароль;
   - при `--keep-groups` оставить группу, иначе применить `--group-map`;
   - сформировать строку только из белого списка колонок.
6. Проверить уникальность email и псевдонимов (`dict` до записи); при коллизии — ошибка с номером строки.
7. Записать выход атомарно: сначала `*.tmp`, затем `os.replace`; кодировка `utf-8-sig`, `lineterminator="\n"`.
8. Записать mapping (если запрошен) и отчет: всего строк, успешно, ошибок, предупреждений, распределение по группам/полу.
9. В режиме `--verify` дополнительно выполнить проверки из раздела 8 и вернуть ненулевой код при провале.
10. `--dry-run` — все шаги, кроме записи файлов.

Требования к детерминизму:

- пиновать точную версию Faker (`pip freeze > requirements.txt`);
- не менять порядок строк и locale;
- `Faker.seed()` вызывать на каждую строку от псевдонима, а не от номера строки;
- повторный запуск с теми же входом, секретом и seed обязан давать побайтово тот же выход (проверяется `diff`).

## 7. Пошаговый план работ

### Этап 0. Подготовка (15 мин)

1. Создать каталог `C:\anon-labbooking\` и подкаталоги из раздела 5.
2. Создать venv и установить Faker:
   ```bash
   cd /c/anon-labbooking
   python -m venv .venv
   .venv/Scripts/pip install Faker
   .venv/Scripts/pip freeze > requirements.txt
   ```
3. Сгенерировать секрет (не через историю команд, а менеджером паролей или Python-скриптом с записью в файл):
   ```bash
   .venv/Scripts/python -c "import secrets,pathlib; pathlib.Path('../secret/anon.key').write_text(secrets.token_hex(32))"
   ```
4. Положить реальный CSV в `input/`, убедиться, что он не лежит в синхронизируемой папке и не отслеживается git.

### Этап 1. Аудит входного CSV (20 мин)

1. Выписать фактический список колонок.
2. Определить: есть ли `dekanat_id`/`student_id`/`email`, в каком виде `gender`, какой разделитель и кодировка.
3. Проверить, что в файле нет лишних ПДн-колонок, которые нужно отбросить.
4. Решить судьбу `group`/`faculty`: оставляем или маппим. Если маппим — подготовить `group-map.csv` (`real_group,pseudo_group`) и применить ее также к `groups.csv`.

### Этап 2. Реализация скрипта (2–3 ч)

1. Каркас CLI и чтение конфигурации.
2. Функции псевдонимизации и нормализации пола.
3. Генерация ФИО с per-row seed.
4. Белый список колонок, запись выхода и mapping.
5. Отчет и коды возврата.
6. Режимы `--dry-run` и `--verify`.

### Этап 3. Самопроверка скрипта (30 мин)

1. Прогнать на синтетическом мини-CSV (5 строк, все варианты пола и пустых ID).
2. Прогнать дважды на реальном входе, сравнить выходы:
   ```bash
   .venv/Scripts/python anon_students.py ... --output output/a.csv
   .venv/Scripts/python anon_students.py ... --output output/b.csv
   diff output/a.csv output/b.csv
   ```
3. Проверить, что в выходе нет реальных значений (см. раздел 8).
4. Просмотреть 10 случайных строк глазами: имя/отчество согласованы с полом, email выглядит корректно.

### Этап 4. Подготовка тестовой БД (20 мин)

1. Поднять чистую тестовую БД/контейнер, не трогая прод.
2. Импортировать инфраструктуру и справочники в порядке:
   ```bash
   cd backend
   python manage.py seed_demo
   python manage.py import_dekanat_csv ../anon-labbooking/output/disciplines.anon.csv --type disciplines
   python manage.py import_dekanat_csv ../anon-labbooking/output/groups.anon.csv --type groups
   python manage.py import_dekanat_csv ../anon-labbooking/output/lab_bindings.anon.csv --type lab_bindings
   python manage.py import_dekanat_csv ../anon-labbooking/output/curriculum.anon.csv --type curriculum
   python manage.py import_dekanat_csv ../anon-labbooking/output/staff.anon.csv --type staff
   python manage.py import_dekanat_csv ../anon-labbooking/output/teachers.anon.csv --type teachers
   ```
   Если остальные файлы пока реальные и не обезличены — импортировать только `groups` и `students`, а остальное не затрагивать.
3. Смоук-импорт одной группы:
   ```bash
   python manage.py import_dekanat_csv ../anon-labbooking/output/students.anon.csv \
     --type students --only-groups "НГФ-21-1" --default-password "changeme123"
   ```
   Убедиться: «Создано: N», ошибок нет, студенты видны в интерфейсе.

### Этап 5. Полный импорт (20 мин)

1. Импортировать весь файл:
   ```bash
   python manage.py import_dekanat_csv ../anon-labbooking/output/students.anon.csv \
     --type students --default-password "changeme123"
   ```
2. Повторить импорт и убедиться, что это апдейт, а не дубли:
   - второй запуск должен дать «Создано: 0», «Обновлено: N»;
   - в БД число студентов не изменилось.
3. Проверить выборкой:
   - все `email` заканчиваются на `@demo.local`;
   - все `dekanat_id`/`student_id` соответствуют шаблону `STU-[DS]-[0-9a-f]{10}`;
   - `phone` пуст;
   - `gender` только `M`/`F`;
   - число профилей равно числу строк в CSV (минус отброшенные).

### Этап 6. Очистка (10 мин)

1. Если mapping больше не нужен — удалить `mapping/students.map.csv` и секрет.
2. Реальный CSV — удалить или убрать в защищенное хранилище согласно политике; в корзину не класть.
3. Удалить промежуточные `a.csv`/`b.csv`, `*.tmp`.
4. Проверить, что в репозитории нет новых файлов: `git status`.
5. Зафиксировать в рабочем журнале факт обезличивания и место хранения секрета/исходника, если они сохранены.

## 8. Валидация и критерии приемки

Проверки, которые должны проходить автоматически (`--verify`):

- [ ] число строк на выходе = числу строк на входе минус строки с явными ошибками; ошибки перечислены в отчете;
- [ ] `first_name`, `last_name` непустые в каждой строке;
- [ ] `gender` ∈ {`M`, `F`}, и отчество оканчивается на `-вич`/`-вна` соответственно (мягкая проверка с предупреждением);
- [ ] все email уникальны и в домене из конфига;
- [ ] все псевдонимы уникальны там, где уникальны исходные ID;
- [ ] ни одно реальное значение из входных колонок ФИО/ID/email/phone не встречается в выходе (поиск без учета регистра, кроме разрешенных колонок вроде `group`, если они сохранены);
- [ ] повторный запуск с теми же параметрами дает идентичный файл (`diff` пуст);
- [ ] в выходном заголовке нет колонок вне белого списка.

Проверки после импорта:

- [ ] повторный импорт не создает дубликатов;
- [ ] вход в систему под тестовым студентом работает с дефолтным паролем;
- [ ] карточка студента показывает синтетические ФИО и корректные инициалы в шапке;
- [ ] в админке/списках нет реальных email и телефонов;
- [ ] записи на слоты и посещаемость создаются, как раньше.

## 9. Риски и меры

| Риск | Мера |
|---|---|
| Повторный импорт создает дубликатов | стабильные HMAC-псевдонимы + проверка «Создано: 0» на втором прогоне |
| В CSV остались реальные email/телефон/ID | белый список колонок + автоматический скан выхода |
| Утечка mapping или секрета | хранение вне репозитория, удаление после импорта, не передавать через CLI-аргументы |
| Смена версии Faker меняет имена | точная версия в `requirements.txt`, зафиксированный locale |
| Группа + расписание позволяют сопоставить псевдоним с человеком | при необходимости маппить группы и имена групп во всех CSV согласованно |
| Excel портит CSV | не открывать файл Excel-ом; при необходимости использовать `utf-8-sig` и проверить заголовок после сохранения |
| Случайное совпадение синтетического ФИО с реальным человеком | считать данные тестовыми, не публиковать их как «анонимный датасет» |
| Импорт в не ту БД | отдельный `.env`, проверка подключения, запрет запуска на prod-хосте |
