# Админка и служебные команды

**Проект:** labbooking2-main
**Дата:** 18.11.2026

## 1. Что в админке только для чтения

Следующие модели открыты в админке для просмотра, но не для правки:

- `Booking` — записи студентов;
- `BookingStatusHistory` — история статусов;
- `AuditLog` — аудит действий.

У них отключены добавление, изменение и удаление. Причина простая: статус записи меняет не только поле `current_status`, но и счётчики неявок, уведомления, очередь и аудит. Правка через форму обходила бы все эти шаги.

Статусы меняются через интерфейс сотрудника или завлаба. Если нужна аварийная правка, которой нет в интерфейсе, это делается отдельной командой или через shell с записью в `AuditLog`, а не через админку.

## 2. Справочники

У `LabWork`, `Discipline` и `LabSession` запрещено удаление через админку. ЛР и дисциплины архивируются в портале завлаба: `is_archived=True`, история записей и слотов остаётся. Слоты отменяются, а не удаляются.

## 3. Команды

### `recount_attendance`

Сверяет `StudentLabAttendance.no_show_count` с фактическими записями, у которых `had_no_show=True`.

```bash
python manage.py recount_attendance          # только отчёт
python manage.py recount_attendance --apply  # записать исправления
```

Флаг `explanation_required` команда не трогает: его снимает сотрудник вручную, счётчик при этом сохраняется.

### `archive_old_data`

Показывает старые отменённые слоты и записи аудита. По умолчанию ничего не удаляет.

```bash
python manage.py archive_old_data          # отчёт
python manage.py archive_old_data --apply  # удалить
```

Слоты, у которых есть записи студентов, остаются: `Booking.lab_session` защищён `PROTECT`.

### `import_dekanat_csv`

Импорт CSV из Деканата. Пароли существующих пользователей не меняются; для массового сброса есть отдельный флаг.

```bash
python manage.py import_dekanat_csv students.csv --type students
python manage.py import_dekanat_csv students.csv --type students --reset-passwords
```

Роль и `is_staff` существующего аккаунта не меняются. Если в CSV указана другая роль, строка пропускается с причиной. Ошибки выводятся с номером строки, полем и причиной; одна плохая строка не останавливает файл.

## 4. Уведомления

Транспорт уведомлений пока не подключён: `apps/bookings/notifications.py` формирует текст и пишет его в лог. Это честно отражено в коде и документации; сообщения «уже отправлено» из комментариев убраны.

## 5. Правило на будущее

Если появляется новая операция, которая меняет статус, счётчик или очередь, она оформляется сервисом или командой. Админка остаётся просмотром, а не вторым интерфейсом записи.
