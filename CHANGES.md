# Изменения: переработка ядра бронирования

**Дата:** 18.11.2026
**Проект:** labbooking2-main
**План:** `docs/PLAN_BOOKING_CORE_2026-11-18.md`
**Журнал работ:** `docs/WORKLOG_BOOKING_CORE_2026-11-18.md`

## Что изменилось

- Вместимость слота больше не хранится в базе. Мест на пару = `LabWork.capacity`, для групповой брони — размер группы.
- Стенды задаются у лабораторной работы набором `LabWork.stands`, а не у слота. Одна ЛР может идти параллельно в нескольких аудиториях, если у неё там есть стенды.
- Аудитория ограничивает запись всегда: сумма записей на пересекающиеся слоты комнаты не больше её вместимости.
- Ручная запись блокируется только занятым стендом. Переполнение аудитории даёт предупреждение, запись сверх лимита попадает в аудит и отчёт «Переполненные слоты».
- Изменение вместимости аудитории пишется в аудит; после уменьшения показываются затронутые слоты.
- Добавлен частичный уникальный индекс: у студента не может быть двух активных записей на один слот.
- Записи, слоты, ЛР и дисциплины защищены от удаления с историей (`PROTECT`); ЛР и дисциплины архивируются.
- Админка по броням, истории статусов и аудиту — только для чтения.
- Массовые операции со слотами атомарны. Ошибка на середине серии или копирования откатывает всю операцию.
- Импорт деканата не меняет пароли и роли существующих пользователей без явных флагов.
- `archive_old_data` по умолчанию только отчитывается, удаляет по `--apply`.
- Добавлена команда `recount_attendance` для сверки счётчиков неявок.
- Очередь на слот: промоушен идёт под блокировкой слота и повторным чтением очереди.
- Права: преподаватель видит только свои слоты и записи, сотрудник пишет только в закреплённые аудитории, завлаб — вся лаборатория.
